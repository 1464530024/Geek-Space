# 极客空间 · Geek Space

设备信息与硬件监控工作台。覆盖 Windows 桌面端与 Android 移动端，面向「搞机党」个人使用，不含盈利与广告，可通过安装包直接分发。

当前版本：**v0.1.0 可交互高保真原型**（纯前端，打开即用）

---

## 运行方式

无需任何构建环境，双击打开即可：

```
geek-space/index.html
```

或本地起一个静态服务（推荐，避免个别浏览器对 `file://` 的限制）：

```bash
cd geek-space
npx --yes serve .        # 或 python -m http.server 8080
```

首次打开会进入引导页（欢迎 → 色彩风格 → 语言 → 桌面视觉风格）。移动端自动跳过第三步。

## 设计定调

| 维度 | 决策 |
|---|---|
| **目的** | 给搞机玩家的一体化设备信息与硬件监控工作台，一屏看清 CPU / GPU / 内存 / 存储 / 电池的实时状态 |
| **调性** | 工业实用（Industrial/utilitarian）—— 高密度信息、等宽数字、发丝边框、单色强调，叠加极客控制台的科技氛围 |
| **记忆点** | 「整机功耗」环形仪表 + 32 格核心负载矩阵：一眼看出谁在吃电、哪个核在跑满 |
| **展示字** | `Chakra Petch`（拉丁，科技感；不在 AI 味禁用清单内） |
| **数字字** | `JetBrains Mono`（全部指标 `tabular-nums` 对齐，读数不跳动） |
| **正文字** | `IBM Plex Sans` + 中文系统字（微软雅黑 / 苹方 / Noto Sans CJK） |
| **主色** | 深色 `#0a0b0d` ／ 浅色 `#f2f6f3`；**唯一强调色：绿**（深色 `#2bc97e`，浅色 `#12a05c`） |
| **状态色** | 绿=正常 / 琥珀=注意 / 红=异常 / 蓝=信息，语义固定不随主题变 |

**反 AI 味自检**：无 Inter/Roboto/system-ui 展示字；无白底紫蓝渐变；首屏非「居中标题+副标题+两个按钮+三张卡」；动效为一次编排的错峰入场（6 组，间隔 70ms）；有氛围层（极客风工程网格+顶部光晕 / 苹果风径向色洗）；组件覆盖默认/悬停/聚焦/禁用/空态/加载态；全站 `:focus-visible` 可见描边。

## 主题矩阵

两层主题互相正交，共 **2 × 3 = 6 种组合**；移动端锁定统一风格以避免颜色污染。

| 层 | 取值 | 作用位置 |
|---|---|---|
| `data-theme` | `dark` 黑色深色 / `light-green` 白色+绿色 | `<html>` |
| `data-style` | `geek` 极客风 / `minimal` 简约风 / `apple` 苹果风 | `<html>`（**仅桌面端**） |

| 视觉风格 | 圆角 | 阴影 | 背景 | 典型场景 |
|---|---|---|---|---|
| **极客风** | 2–9px 方角 | 无（靠边框分层） | 40px 工程网格 + 顶部绿色光晕，卡片四角括号 | 仪表盘密度、等宽数字、发丝边框 |
| **简约风** | 7–16px | 极淡三级 | 纯净无纹理 | 大留白、细线条 |
| **苹果风** | 11–21px + 胶囊 | 柔和三级 | 径向色洗 + 毛玻璃 `backdrop-filter` | 大圆角、柔和层次 |

切换入口：引导页第 3 步、设置页「外观」、顶栏右侧风格按钮（桌面端循环切换）。

## 已实现功能

**1. 实时硬件监控**
- 概览页：实时趋势曲线（CPU/GPU/内存三线）、整机功耗环形仪表 + 功耗分解、四联环形指标（CPU 使用率/温度/频率/功耗、GPU、内存、系统盘）、设备信息、快速状态、进程 TOP
- 硬件监控页 7 个页签：
  - **处理器**：型号/代号/制程/核心线程/基准频率/三级缓存/TDP/插槽 + 使用率温度双环 + **核心负载矩阵**（逐逻辑核 使用率/温度/频率）
  - **内存**：容量/类型/频率/通道/已用/可用/虚拟内存 + 插槽明细
  - **显卡**：型号/显存/驱动/核心与显存频率/总线/TDP + 负载温度双环
  - **主板**：厂商/型号/芯片组/BIOS 版本与日期/EC 版本
  - **显示器**：型号/分辨率/刷新率/尺寸/面板/HDR/序列号
  - **存储**：硬盘表（型号/接口/容量/已用/健康度/温度/顺序读写）+ 分区卷表 + 实时吞吐曲线 + SMART 详情
  - **电池**：健康度大环 + 设计容量/满充容量/循环次数/电压/温度/剩余时间/功率

**2. 有线连接联动**
- 连接卡：设备名/型号/Android 版本/序列号/连接方式（USB / 无线调试）/存储占用
- **应用管理**：36 个真实包名样本，系统/普通分类、风险标记（安全 / 需谨慎 / 高危），支持搜索、筛选、**卸载 / 冻结 / 还原**
- **文件管理**：路径面包屑 + 目录/文件列表 + 下载/删除
- 未连接时展示引导空态与重新扫描入口

**3. 主动补充的搞机功能**
- **设备跑分**：单核 / 多核 / 图形 / 内存 + 综合得分 + 性能档位（S/A/B/C）+ 扫描动画 + 历史记录
- **传感器**：14 项（温度 / 电压 / 风扇 / 功耗）实时值 + 最低/最高
- **启动项 / 服务**：12 项，发行者、启动类型（自动/手动）、启用/禁用开关
- **驱动与固件**：BIOS / EC / ME 固件卡 + 8 项驱动版本与日期

**4. UI 与设置**
- 首次引导页（4 步）+ 设置页可随时修改
- 色彩风格、桌面视觉风格、界面语言、刷新频率（0.5s/1s/2s/暂停）、温度单位（°C/°F）、显示功耗/风扇开关
- 导出设备报告（JSON）、恢复默认设置、重新运行引导页

## 从原型到原生（Tauri 2 移植映射）

前端为框架无关的原生 HTML/CSS/JS，**可直接作为 Tauri 的 `frontendDist` 打包，无需重写**。只需把 `Monitor` 模块的模拟实现替换为 Rust 侧真实采集：

| 模块 | 原型（当前） | 原生（Tauri 2 + Rust） |
|---|---|---|
| 基础硬件 | `monitor.js` 正弦漂移模拟 | `sysinfo` crate（CPU/内存/磁盘/进程） |
| 温度/电压/风扇 | 模拟 | 内置 `LibreHardwareMonitorLib` 小助手进程，本地 HTTP/JSON 回传（`hw` 项目同款方案） |
| 显卡 | 模拟 | NVIDIA 走 `nvml-wrapper`；AMD/Intel 走 DXGI / ADL |
| 硬盘 SMART | 模拟 | `smartctl` 或 WMI `MSStorageDriver_FailurePredictStatus` |
| 电池 | 模拟 | Windows `GetSystemPowerStatus` / `IOCTL_BATTERY_QUERY_INFORMATION`；Android `BatteryManager` |
| 手机联动 | 内存内模拟 | Rust `adb_client` 直连（**不需要用户另装 adb**，`adbUI` 同款方案，捆绑 platform-tools） |
| Android 端监控 | — | `/sys/class/thermal`、`/proc/meminfo`、`StatFs`、`SensorManager`（受系统权限限制，温度部分机型不可得） |

**移植时无需改动的地方**：`views/*`、`i18n.js`、`store.js`、`ui.js`、全部 CSS。只需让 Rust 侧按 `Monitor.live` 的同名字段回传数据即可。

## 已知限制

- 原型使用**确定性伪随机 + 负载场景**模拟真实读数（含偶发尖峰、负载等级切换），非真实硬件数据
- 手机联动为交互演示：卸载/冻结/还原仅作用于内存中的演示数据，刷新页面即复位
- 温度单位切换会影响全站温度显示；已同步的环形仪表、核心矩阵、传感器表均实时换算
- 字体走 Google Fonts CDN，离线时回退到等宽/系统字，布局不错位但风格略降。原生打包时应将字体下载进包内

## 后续建议（按优先级）

1. **接入真实硬件**：搭 Tauri 工程 → 接 `sysinfo` + LibreHardwareMonitorLib → 替换 `Monitor`
2. **接入真实 ADB**：`adb_client` + 捆绑 platform-tools，补上应用图标提取、批量操作、任务中心
3. **曲线回放与导出**：把 `Monitor.history` 落盘，支持导出 CSV 与阈值告警
4. **风扇曲线 / 功耗墙**：进阶搞机功能（需驱动级权限，风险较高，建议单独开关）
5. **移动端**：Tauri Android 打包；受系统限制，移动端监控维度会少于桌面端
